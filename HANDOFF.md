## 1. What this is

A Go CLI for **Program Pathways Mapper (PPM / "ProgramMapper")** — the public
academic-pathways platform for California Community Colleges (built by Bakersfield
College / Kern CCD + the CA Community Colleges Chancellor's Office + FoundationCCC).

It publishes the official "how to finish your degree" maps (semester-by-semester
course plans) for ~hundreds of CA community colleges, but only through a click-heavy
Angular SPA with no API key and no export. This CLI **mirrors a college's catalog
into local SQLite**, then runs offline: term-by-term degree plans with unit rollups,
program comparison, catalog-year diffs, course→program reverse lookup, bottleneck
courses, cross-college search, and CSU/UC transfer + career rollups.

Originally generated by **CLI Printing Press**, then forked into a standalone repo
(see §7 for the Printing Press relationship — important).

## 3. The API (reverse-engineered — the most valuable context here)

- **Frontend:** Angular SPA at `https://<college>.programmapper.ws` (target college: `la-mission.programmapper.ws`).
- **Backend API:** `https://b.api.programmapper.com` — discovered from the SPA's `/assets/env-specific.json` (`apiBaseUrl`). REST/JSON, **no auth**.
- **WAF / transport (critical):** the API sits behind a WAF that **403s plain Go `net/http`** but **passes Surf with a Chrome TLS fingerprint**. The CLI ships **Surf transport** (`http_transport: browser-chrome` in `spec.yaml`; see `internal/client/client.go` → `surf.NewClient().Chrome()`). It also **rate-limits bursts per IP** — pace requests; expect 403/429 under load. `doctor` says "API: reachable" when Surf clears it.
- **Multi-tenant:** 954 college records. Each college has one `site-content` per catalog year (`latestSiteContentIdsByYear`, 2019–2025).

### Data model (graph; no flat list endpoints — this shapes the whole design)
```
colleges ──> site-contents (one per college-year)
                 ├─ home-page-content ──> programGroups[] (= interest clusters / "Areas of Interest")
                 │        └─ program-groups/{clusterId} ──> programs[] (summaries)
                 ├─ programs/{programId} ──> pathways[] (each has a programMapId)
                 │        └─ program-maps/{mapId} ──> pathwayElements[]
                 │                 └─ recommendedOpportunity: {type: COURSE|CHOICE|MILESTONE,
                 │                       term{termNumber,year,customLabel}, courseCode, courseName,
                 │                       mappedCourseId, minUnits, maxUnits}, requirement{requirementType}
                 ├─ courses/{courseId} ──> {masterRecordId, courseCode, title, rawMin/MaxUnits, prerequisiteText}
                 ├─ linked-programs/{id}, linked-program-maps/{id}, linked-transfer-colleges/{id},
                 │   choice-opportunities/{id}   (CSU/UC transfer surfaces)
                 └─ programs/{id}/prior-years-with-maps  (per-year prior maps for diffing)
standard-occupations/batch  (POST {standardOccupationalCodes:[...]}) ──> career salary + job-growth
```

### Endpoint quick reference (all GET unless noted; `{scid}` = site-content id)
- `info` → `{version}` (health probe)
- `colleges`, `colleges?url=<full vanity URL incl. scheme>`, `colleges/{id}`
- `site-contents/{scid}`, `site-contents/{scid}/home-page-content`
- **`site-contents/{scid}/program-groups/{clusterId}`** ← cluster detail (lists programs)
- `POST site-contents/{scid}/programs/search` body `{searchString}`
- `site-contents/{scid}/programs/{programId}` (+ `/pathways`, `/prior-years-with-maps`, `/newer-year-link-data`)
- `site-contents/{scid}/program-maps/{mapId}`, `/linked-program-maps/{mapId}`, `/linked-programs/{programId}`
- `site-contents/{scid}/courses/{courseId}` (+ `/highSchools`)
- `site-contents/{scid}/choice-opportunities/{id}`, `/linked-transfer-colleges/{id}`
- `POST standard-occupations/batch`

### ⚠️ Gotchas learned the hard way
- **`interest-clusters/{id}` is a front-end ROUTE, not an API path.** The real cluster-detail API path is `program-groups/{clusterId}` (the spec's `interest-clusters` resource is wired to `/program-groups/{cluster_id}` for exactly this reason).
- **`colleges?url=` needs the full URL with scheme** (`https://la-mission.programmapper.ws`), not the bare hostname (returns `[]` otherwise).
- **`linked-programs/{programId}` returns 404 for a normal programId** — transfer linkage is reached via the pathway `next` field + the linked-* endpoints, not by re-keying the program id. `transfer-options` instead surfaces transfer pathways (from the program's `pathways[].label`, e.g. "to CSU - Cal-GETC") + a career-outlook join (program's `careerStandardOccupationalCodes` → `standard-occupations/batch`).
- **Unknown ids often return HTTP 200 + empty body** (not 404) — see the `pp:no-error-path-probe` annotations in §6.
- The map JSON's `programId`/`programTitle`/`programAward` fields are **mislabeled/shuffled** by the API; don't trust them. The mirror injects `pmProgramId`/`pmProgramTitle`/`pmAward` so `course-programs`/`bottlenecks` can link maps→programs reliably.

## 4. Commands

**Mirror first** (transcendence commands read the local mirror):
```bash
programmapper-cli mirror la_mission           # light: clusters + program summaries (~8 reqs, fast)
programmapper-cli mirror la_mission --maps    # deep: + every program's map + courses (paced, resumable)
#   --max-programs N    cap the deep pass
```

Generated endpoint commands (20): `colleges {list,get,resolve}`, `site-contents {get,home}`,
`interest-clusters`, `programs {get,search,pathways,prior-years,newer-year-link,linked}`,
`program-maps {get,linked}`, `courses {get,high-schools}`, `transfer {linked-college,choice-opportunity}`,
`occupations`, `meta`. (`interest-clusters`, `meta`, `occupations` are *promoted* single-endpoint commands — no sub-verb.)

Transcendence (hand-built, novel) commands:
| Command | What | Data source |
|---|---|---|
| `plan <programId>` | term-by-term plan, units rollup, expands COURSE/CHOICE/MILESTONE | local mirror, **live fallback** for the map |
| `compare <progA> <progB>` | shared/unique courses + units side by side | auto (local + live fallback) |
| `diff-years <programId> --from-year YYYY` | added/removed courses vs a prior catalog year | current local, prior fetched **live** |
| `course-programs <courseIdOrCode>` | reverse lookup: which programs require a course | **local only** (scans mirrored maps) |
| `bottlenecks [--limit N]` | rank courses by how many maps require them | **local only** |
| `transfer-options <programId>` | transfer pathways (CSU/UC) + career salary outlook | auto (program local, careers live) |

Framework commands worth knowing: `search` (FTS — **use `--data-source local`**, see §6), `sync`, `doctor`,
`agent-context`, `which`, `workflow`, `export`/`import`, `profile`, `feedback`.

Global flags: `--agent` (= `--json --compact --no-input --no-color --yes`), `--json`, `--select <dotted.paths>`,
`--data-source auto|local|live`, `--db <path>`, `--timeout` (per-request), `--rate-limit`.

```
  promoted_*.go                      GENERATED single-endpoint promoted commands
  pmstore.go        ★ hand-written   shared models (pmProgram/pmMap/pmOpportunity/...), store loaders,
                                     pmResolveSiteContent, pmLoadProgramMap, pmIsRateLimited, pmMapCourses, etc.
  mirror.go         ★ hand-written   the graph-walk mirror (paced, resumable, backoff-retry on throttle)
  plan.go compare.go diff_years.go course_programs.go bottlenecks.go transfer_options.go  ★ hand-written novel commands
  transcend_test.go ★ hand-written   table-driven tests for the pure logic (buildPlan/buildCompare/buildDiffYears/...)
  helpers.go        GENERATED        printJSONFiltered, dryRunOK, boundCtx, defaultDBPath, error ctors (usageErr/notFoundErr/rateLimitErr/...)
  search.go         GENERATED        framework FTS search (NOTE the broken auto live path, §6)
  sync_hint.go      GENERATED        hintIfUnsynced / hintIfStale
```
★ = hand-written; everything else is generated and carries a `// Generated by CLI Printing Press ... DO NOT EDIT` header.

**Store conventions:** the mirror upserts into the generic `resources` table under these `resource_type`
keys (constants in `pmstore.go`): `site_contents`, `interest_clusters`, `programs`, `program_maps`, `courses`.
`db.Upsert(type,id,data)` also indexes `resources_fts`, so `search --type programs --data-source local` finds them.
Maps store an injected `pmProgramId`/`pmProgramTitle`/`pmAward` for reliable map→program linking.

## 6. Key decisions & quirks (don't re-derive these)

- **Surf transport is mandatory** (WAF blocks stdlib HTTP). Don't "simplify" the client back to `net/http`.
- **The mirror is the data layer.** ProgramMapper has no flat `/programs` list, so offline anything requires the
  graph walk in `mirror.go`. `plan`/`compare`/`transfer-options`/`diff-years` fall back to live fetch when the map
  isn't mirrored; `course-programs`/`bottlenecks` are **local-only** (they need the mirrored map set).
- **Framework `search` auto-mode is broken for this API.** `internal/cli/search.go` hard-codes a per-tenant live
  search endpoint (`POST /site-contents/{site_content_id}/programs/search` with a *literal* placeholder + wrong body)
  and won't fall back to local on a non-network error. **Always invoke `search ... --data-source local`** (the
  cross-college FTS is inherently offline anyway). All docs/examples already do this. This is a generator bug; left
  unedited to stay regen-safe in the library copy, but in THIS standalone repo you may hand-fix `search.go` to be
  local-only if desired.
- **`pp:no-error-path-probe` annotations** on `course-programs`, `site-contents get`, and `programs search` — these
  commands return gracefully (exit 0) for "invalid" input (local search = empty result; API returns 200-empty for
  unknown ids; per-tenant search needs a positional scid). The annotation tells dogfood to skip the error-path probe.
- **NULL-safe SQL + typed nullable salary fields** (`*float64` in `transfer_options.go`) — the careers API returns
  `null` for some salary fields; pointers preserve that vs. coercing to 0.
- **Naming after the standalone rename:** module = `github.com/johnnyrobot/programmapper-cli`; binary/skill =
  `programmapper-cli` / `programmapper`. **But** the User-Agent strings (`programmapper-cli/deliver`,
  `programmapper-cli/feedback`) and the app-dir name (`appName = "programmapper-cli"`, config at
  `~/.config/programmapper-cli/`) intentionally stay as the bare binary name — they are NOT module paths.

## 7. Printing Press relationship (read before regenerating anything)

This repo **forked away** from CLI Printing Press. Consequences:
- The generator names CLIs `<slug>-pp-cli`. This repo dropped the `-pp`, so **a Printing Press regen/reprint would
  re-introduce `programmapper-pp-cli`** and overwrite the rename + module path. Don't run PP regen against this repo.
- The **untouched, PP-compatible copy lives at `~/printing-press/library/programmapper/`** (`programmapper-pp-cli`,
  module `programmapper-pp-cli`). Use that copy for any Printing Press tooling (`/printing-press-polish`,
  `/printing-press-reprint`, `/printing-press-publish`, `/printing-press-score`), then cherry-pick results here.
- Vestigial PP metadata still present in this repo (`.printing-press.json`, `.printing-press-patches/`,
  `AGENTS.md` saying "treat fixes as upstream Printing Press fixes"). Harmless, but they describe a workflow this
  fork has stepped away from. Safe to delete if you want a cleaner repo.

## 11. Gotcha cheat-sheet for the next session

- API blocked by WAF? You're using stdlib HTTP — must use Surf/Chrome fingerprint (already wired in the client).
- `search` returns empty? Add `--data-source local` (and `mirror` first).
- `plan`/`compare` say "no local mirror"? Run `mirror <college> --maps` (or pass `--site-content <scid>`).
- A command exits 0 on junk input? Expected for local-search / 200-empty-id commands (see `pp:no-error-path-probe`).
- Cluster detail 404s at `interest-clusters/{id}`? Use `program-groups/{id}` (front-end route ≠ API path).
- Want to use Printing Press tooling? Use `~/printing-press/library/programmapper/`, NOT this repo.
